# 多言語サイト

1つのリポジトリから、日本語と英語のように複数の言語のサイトを作れます(v1.28.0以降)。
翻訳のページは、元のページと同じ場所に、ファイル名の後ろに言語を付けて置きます
(`docs/cli.md`の英語版なら`docs/cli.en.md`)。

## サイトの言語を決める(`LANGUAGES`)

`.github/docs-pages.config`の`LANGUAGES`に、サイトの言語をカンマ区切りで書きます。

```
LANGUAGES=ja,en
```

- **先頭の言語が「基本言語」**です。起点のREADME(`ROOT_MD`)と、言語を付けないファイルの言語で、
  URLが今までどおりになる言語です。READMEの言語を先頭に書いてください。
- 言語が1つなら1言語のサイト、2つ以上なら多言語のサイトになります。
- 書かなかった場合(キーが無い、または値が空)は`en`(英語の1言語サイト)です。

| READMEの言語 | 作りたいサイト | 書き方 |
|---|---|---|
| 日本語 | 日本語だけ | `LANGUAGES=ja` |
| 日本語 | 日本語+英語 | `LANGUAGES=ja,en` |
| 英語 | 英語+日本語 | `LANGUAGES=en,ja` |

言語は`ja`・`en`・`pt-BR`・`zh-Hant`のような言語タグで書きます。正しくない値や重複の扱いは
[設定リファレンス](configuration.ja.md#languages)を参照してください。

> [!NOTE]
> 以前の設定キー`LANG`は廃止しました。書かれていても警告を出して無視されるので、
> `LANGUAGES`に書き直してください(例: `LANG=ja`なら`LANGUAGES=ja`)。

## ファイルの置き方

例: `LANGUAGES=ja,en`(READMEが日本語)

```
README.md            … 日本語(基本言語)のトップ
README.en.md         … 英語のトップ
docs/cli.md          … 日本語
docs/cli.en.md       … 英語
docs/faq.md          … 日本語だけ(英語版なし)
guide/README.md      … 日本語のフォルダの入口
guide/README.en.md   … 英語のフォルダの入口
images/a.png         … 画像はすべての言語で共通
```

他の言語のトップは、`ROOT_MD`に言語を付けた名前(`README.md`なら`README.en.md`)です。
フォルダを言語ごとに写す必要はありません。

### ファイルの言語の決め方

1. ファイル名が`名前.<言語>.md`の形で、`<言語>`が`LANGUAGES`のどれか(基本言語を含む)と一致すれば、
   その言語のページです(大文字・小文字は区別しません)。
2. それ以外のファイルは、すべて基本言語のページです。`config.example.md`や`v2.0.md`のように、
   `LANGUAGES`に無い言葉が付いた名前も、普通の名前として基本言語になります。
3. 同じページの基本言語版として、基本言語を付けたファイルと付けないファイルの両方があれば、
   付けた方を使います([次の節](#基本言語を付けたファイルの優先))。

言語の付け方が同じ名前(`cli.md`と`cli.en.md`)どうしが、同じページの別の言語版として
自動で結び付けられます。

### 基本言語を付けたファイルの優先

基本言語にも言語を付けられます。たとえば`LANGUAGES=en`のとき、`README.en.md`と`README.md`が
両方あれば`README.en.md`がサイトのトップになり、`README.md`はサイトに出ません
(使わなかったファイルは、ビルドのログに
`Not used (a marked base-language file is used instead): README.md → README.en.md`のように表示されます)。GitHubで表示される`README.md`を、
サイトとは別の短い案内にしたいときに使えます。印の無いファイルへのリンクは、印の付いた方への
リンクとして扱われるので、リンク切れにはなりません。1言語のサイトでも同じです。

`README.md`が日本語で`README.en.md`が英語のとき、どちらを基本言語にするかで書き方が2つあります。

- **`README.md`をそのまま日本語のトップにする**: `LANGUAGES=ja,en`にします。
  日本語が今までどおりのURL、英語が`/en/`の下になります。
- **英語を基本言語にする**: `LANGUAGES=en,ja`にして、日本語版を`README.ja.md`という名前で置きます。
  このとき`README.md`はサイトに使われません(印の無いファイルは、常に基本言語として扱われます)。

## URLの形

基本言語のページは今までどおりのURLで、ほかの言語のページは`/<言語>/`の下に出力されます。

| ファイル | URL(`LANGUAGES=ja,en`) |
|---|---|
| `README.md` | `/`(`README.html`) |
| `README.en.md` | `/en/` |
| `docs/cli.md` | `/docs/cli.html` |
| `docs/cli.en.md` | `/en/docs/cli.html` |
| `guide/README.en.md` | `/en/guide/` |

URLの言語の部分は小文字になります(`pt-BR`なら`/pt-br/`)。基本言語を付けたファイルは、
付けない名前のURLになります(`LANGUAGES=en`の`docs/cli.en.md`は`/docs/cli.html`)。
リポジトリに`en/`のような、基本言語以外の言語と同じ名前のフォルダがあると、出力先が重なるおそれがあるため
警告が表示されます(基本言語のページは`/<言語>/`の下に出力しないので、基本言語と同じ名前のフォルダは対象外です)。

## 本文のリンクの書き方

- **ファイルへのリンクは、書いたとおりのページに飛びます。** 英語のページから英語のページへは
  `cli.en.md`のように、言語を付けた名前でリンクします。`cli.md`と書くと日本語のページに飛びます。
- **フォルダへのリンク**(`guide/`)と**サイトのトップへのリンク**(`/`)は、リンク元のページの言語の
  入口に飛びます(英語のページからなら`/en/guide/`・`/en/`)。その言語の入口が無ければ、基本言語の
  入口に飛びます。
- 画像へのリンクはどの言語のページからでも同じ画像を指すので、そのままで構いません。

> [!WARNING]
> 見出しへのリンク(`cli.en.md#options`)は、リンク先のページの見出しで決まります。翻訳で見出しの
> 文言が変わると、元の言語の見出しへのリンクはそのままでは切れます。リンク先の言語の見出しに
> 合わせて書いてください(`STRICT_LINKS=true`なら、ビルドが止まって気づけます)。

## ナビ・前後のページ・検索

ナビ・「前のページ/次のページ」・サイト内検索は、言語ごとに別々に作られ、**今の言語のページだけ**が
載ります。

- **並び順**: 基本言語のナビは今までどおり、READMEでリンクを書いた順です。ほかの言語のナビは、
  対応する基本言語のページの順に並び、翻訳にしか無いページは後ろに付きます(翻訳のREADMEで
  リンクを書いた順にはなりません)。並びを変えたいときは、frontmatterの
  [`order`](frontmatter.ja.md#order)を使います。`order`は言語ごとのナビでそれぞれ効きます。
- **翻訳の無いページ**: その言語のナビ・前後のページ・検索には出ません。ビルドのログに、
  翻訳の無いページの一覧が表示されます。

## 翻訳は自動で集められます

ページを集めるときは、今までどおりREADMEからリンクをたどります。そのうえで、集めたページの別の
言語版のファイルがあれば、リンクが無くても自動で集めて公開します。

そのため、書きかけの翻訳(`draft.en.md`など)も、`draft.md`が公開されていれば一緒に公開されます。
公開したくない翻訳は、リポジトリに置かないでください。ナビから外すだけでよければ、そのページの
frontmatterに[`nav: false`](frontmatter.ja.md#nav)を書きます。

## 言語の切り替えボタン

多言語のサイトでは、各ページに言語の切り替えボタンが付きます。

- **置き場所**: ナビがあるとき(`NAV_ENABLED=true`)はナビの見出しの横(ライト/ダーク切り替えの手前)、
  ナビが無いときは本文の右上です。
- **形**: 2言語なら、もう一方の言語名のボタンです。3言語以上なら、押すと言語の一覧が開くメニューに
  なります。どちらもふつうのリンクで、JavaScriptは使いません。
- **翻訳の無いページ**: ボタンはその言語のトップページに飛び、翻訳が無いことを知らせる説明が付きます。
  その言語のトップページも無ければ、その言語はボタンに出ません。
- ブラウザの言語に合わせて自動で切り替えたり、選んだ言語を覚えたりはしません。言語はURLだけで
  決まるので、共有したリンクは誰が開いても同じ言語のページになります。

404ページ・1言語のサイトにはボタンは付きません。

## そのほかの動き

- **画面の文言**: 「メニュー」「コピー」「前のページ」などの決まった文言は、ページの言語になります。
- **サイト名**: `SITE_NAME`・`OGP_DEFAULT_IMAGE`はすべての言語で共通です。ページごとの説明文や
  OGP画像は、今までどおりfrontmatterで変えられます。
- **検索エンジン向け**: `<html lang>`はページの言語になります。サイトのURLが分かるとき
  (GitHub Actionsでビルドしたとき)は、別の言語版の場所を検索エンジンに伝える`hreflang`の印も
  出力され、`sitemap.xml`にはすべての言語のページが載ります。
- **404ページ**: [次の節](#404ページ)を参照してください。

## 404ページ

GitHub Pagesは、存在しないURLには`/ja/`の下でも、サイトの一番上にある1枚の`404.html`を返します。
そのため404ページはサイトに1つだけです。多言語のサイトでは、その1枚の中で、開かれたURLの言語の
案内を表示します(v1.29.0以降)。

- `404.md`に、言語ごとの案内を`lang`付きのかたまりで、ページの直下に書きます。

  ```markdown
  <div lang="en">

  # Page not found

  The page you're looking for may have been moved or deleted.

  </div>

  <div lang="ja">

  # ページが見つかりません

  お探しのページは、移動したか削除された可能性があります。

  </div>
  ```

  `<div lang="…">`の後と`</div>`の前に空行を入れると、中身がMarkdownとして表示されます。
- URLの先頭(`BASE_PATH`の後)がほかの言語の先頭(`/ja/`など)ならその言語のかたまりだけを、
  それ以外なら基本言語のかたまりだけを表示します。`lang`の付かない部分は、どの言語でも表示します。
  URLの言語のかたまりが無いときは、何も隠しません。
- 判定はページの中の小さなスクリプトが行います。ナビや「メニュー」などの画面の文言は基本言語の
  ままです。JavaScriptが動かない環境では、すべての言語のかたまりがそのまま表示されます。
- `404.md`が無いときの既定の内容は、トップページのある言語ごとに、お知らせとそのトップページへの
  リンクのかたまりを並べたものなので、同じように表示されます。
- 読むのは基本言語の404(`404.md`、`404.<基本言語>.md`があればそちら)だけです。`404.ja.md`のような
  ファイルは使いません。

## 言語の足し方

1. `LANGUAGES`の後ろに言語を足します(例: `LANGUAGES=ja,en`を`LANGUAGES=ja,en,zh-Hant`に)。
2. 翻訳したいページの横に`名前.<言語>.md`を置きます。まずトップの`README.<言語>.md`を作ってください
   (トップが無い言語は警告が出ます。また、翻訳の無いページの切り替えボタンには、その言語が出ません)。
3. 画面の決まった文言は、Tsuzuri本体の文言の表(`UI_STRINGS`)にある言語(今は英語と日本語)なら
   その言語になります。表に無い言語は英語の文言になります。

## 独自CSSで見た目を変える

言語の切り替えボタンは、次のクラス名で独自CSS(`STYLE_FILE`)から見た目を変えられます。

| クラス名 | 場所 |
|---|---|
| `.tsuzuri-lang-switch` | 言語のボタン(2言語のリンク・3言語以上のメニューのボタン) |
| `.tsuzuri-lang-menu` | 3言語以上のメニュー全体 |
| `.tsuzuri-lang-bar` | ナビが無いときに本文の上に置かれる、ボタンの欄 |

## GitHubでの表示のために

GitHubはリポジトリのトップに`README.md`を表示します。基本言語を付けたファイル(`README.en.md`など)を
サイトのトップにする場合も、GitHubで見た人のために`README.md`を置いておくことをおすすめします
(サイトへの案内や、各言語のREADMEへのリンクなど)。
