# 設定リファレンス(Configuration)

## `.github/docs-pages.config`の場所と書式

設定ファイルは、利用者リポジトリのルートからの相対パスで
`.github/docs-pages.config`に配置します(`npx github:akilasatolu/tsuzuri#v1 init`を実行すると
自動生成されます。詳細は[cli.md](./cli.ja.md))。

書式は「`KEY=VALUE`」形式のシンプルなテキストで、1行につき1項目です。
`#`で始まる行と空行は読み飛ばされます(コメント・区切りとして自由に使えます)。
YAMLのような入れ子構造やクォート、複数行の値には対応していません。
値の前後の空白は取り除かれ、`'`や`"`を含む値もそのまま使われます(引用符も値の一部として
扱われます)。下の一覧にないキーは無視されます(GitHub Actionsの
ワークフローでは警告が出ますが、手元のビルドと`preview`では警告なしで無視されます)。
`#`で始まる行だけがコメントになります。`THEME=nineties  # 90年代風`のように値の後ろに書いた`#`以降は
コメントにならず、値の一部として読まれるので注意してください(コメントは別の行に書きます)。

## 設定キー一覧

### TRIGGER_BRANCH
デプロイをトリガーするブランチ名です。省略した場合(キーが無い、または値が空)は、
リポジトリの既定ブランチ(通常は`main`)になります。このブランチへの
push(マージ含む)があったときだけ、GitHub Pagesへのデプロイが実行されます
(手動実行(`workflow_dispatch`)の場合はこの判定自体がスキップされ、常にデプロイされます。
詳細は[deployment.md](./deployment.ja.md))。
既定ブランチ(通常は`main`)以外を指定する場合は、GitHub側で追加の設定が必要です
([deployment.md](./deployment.ja.md)の「既定ブランチ以外をトリガーブランチにする場合」を参照)。

### ROOT_MD
サイトの起点となるMarkdownファイルの、リポジトリルートからの相対パスです。
デフォルトは`README.md`です。このファイルが実際に存在しない場合や、リポジトリの外を
指している場合、ビルドはエラー終了します。

### OUT_DIR
ビルドしたHTML一式の出力先ディレクトリです。デフォルトは`_site`です。
リポジトリ内のサブディレクトリを指定してください。リポジトリの外やリポジトリ直下
(`.`)を指定した場合は、既存のファイルを上書きしないようビルドをエラー終了します。
キーを省略した・値を空にした場合も`_site`になります(v1.3.0以前のワークフローでは、省略すると
GitHub Pagesへのアップロードで失敗するので、`OUT_DIR=_site`と書いてください)。

ビルドは出力先に目印のファイル(`.tsuzuri-build`)を置きます。次のビルドでは、目印があれば
出力先の中身をすべて消してから書き出すので、削除・改名したページが残りません(v1.5.0以降)。
目印の無いディレクトリ(自分で作ったファイルがあるディレクトリなど)は消しません。

### STYLE_FILE
独自CSSファイルへのパスです。`npx github:akilasatolu/tsuzuri#v1 init`が生成する
`.github/docs-pages.config`では`.github/tsuzuri/styles/custom.css`(組み込みテーマCSSと
同じディレクトリ)が指定されます。このキーを省略した場合も同じ`.github/tsuzuri/styles/custom.css`に
なります。ファイルが無ければ使わない(警告も出さない)ので、独自CSSが不要なら作らなくて構いません。
3層カスケード(基礎CSS→THEME→STYLE_FILE)のうち最も優先度が高い、いわば
「最後に読み込まれて最優先で反映される」層に当たります。ファイルが存在しない場合は
何もせず、既定のスタイルのままビルドされます。
リポジトリの外(`../`で始まるパスや絶対パス、リポジトリ外を指すシンボリックリンク)を指定した場合は、警告を出したうえで無視します。詳細は
[theming.md](./theming.ja.md)を参照してください。

### THEME
組み込みのテーマ(配色+装飾のセット)を選択するキーです。
選択できる値は`material`(マテリアル・既定)/`glass`(グラス)/`neumorphism`(ニューモーフィズム)/`editorial`(エディトリアル)/`minimal`(ミニマル)/`blueprint`(ブループリント)/`nineties`(90年代)/`none`(装飾なし)の8個です。
指定を省略した場合(キーが無い、または値が空)は、警告なしで
`material`になります。上記8個以外の値(例: `sepia`のような存在しない名前)を指定した場合は、
警告(warn)を出したうえで`material`にフォールバックします。
テーマごとの見た目は[theming.md](./theming.ja.md)を参照してください。

### LANGUAGES
サイトの言語です(v1.28.0以降)。`ja`・`en`・`pt-BR`のような言語タグ(BCP 47形式)を、カンマ区切りで書きます。

```
LANGUAGES=ja
```

- **先頭の言語が「基本言語」**です。起点のMarkdown(`ROOT_MD`)と、言語を付けないファイルの言語として
  扱われます。READMEの言語を先頭に書いてください。
- 言語が1つなら1言語のサイトになり、出力されるHTMLの`<html lang="...">`と、画面の決まった文言
  (「メニュー」など)がその言語になります。
- 言語が2つ以上(例: `LANGUAGES=ja,en`)なら多言語のサイトになります。ファイルの置き方などは
  [多言語サイト](./i18n.ja.md)を参照してください。
- 省略した場合(キーが無い、または値が空)は警告なしで`en`(英語)になります。**v1.27.0までの既定値`ja`から
  変わりました。** READMEが日本語なら`LANGUAGES=ja`と書いてください。
- 各言語の前後の空白は取り除かれます。`en_US`のように言語タグとして不正な値や、大文字・小文字を区別せずに
  重複している値は、警告を出したうえでその値だけを無視します。正しい値が1つも無ければ、警告を出して`en`になります。

ページの言語はファイル名と`LANGUAGES`で決まり、frontmatterで変えることはできません(詳細は
[多言語サイト](./i18n.ja.md)を参照)。

> [!NOTE]
> v1.27.0までの設定キー`LANG`は廃止しました。設定ファイルに書かれていても、警告を出したうえで
> 無視されます(`LANGUAGES`に読み替えることはしません)。`LANG=ja`と書いていた場合は`LANGUAGES=ja`に
> 書き直してください。OSの環境変数`LANG`(`ja_JP.UTF-8`など)も使いません。

### NAV_ENABLED
自動生成される簡易ページナビゲーション(サイト内の全ページへのリンク一覧)を
出力するかどうかです。`true`または`false`(大文字小文字は区別しません)のみ有効な値で、
デフォルトは`false`です。省略した場合(キーが無い、または値が空)は警告なしで`false`に
なります。それ以外の値(例: `yes`)を指定した場合は警告を出したうえで`false`扱いになります。

ナビゲーションは、リポジトリのディレクトリ構成に沿った階層構造(入れ子のリスト)で
出力されます。ディレクトリはクリックで折りたためます(v1.7.0以降)。最初はすべてのディレクトリが開いていて、
どのページを見ていても全ページへのリンクが見えます(v1.14.0以降。v1.7.0〜v1.13.0は、いちばん上の階層と
今見ているページがあるディレクトリだけが開いていました)。画面の幅が広い(960px以上)ときは左側に固定したサイドバーとして、
狭いとき(スマートフォンなど)は本文の上に「メニュー」ボタンとして表示され、ボタンを
押すとページ一覧が開きます(JavaScriptは使いません)。ボタンの文言はページの言語が日本語なら
「メニュー」、それ以外なら「Menu」です。

また、各ページの本文の末尾に、ナビの並び順で「前のページ」「次のページ」へのリンクが付き、
ナビの上部にはサイト内検索の検索欄が表示されます([concepts.md](./concepts.ja.md#サイト内検索)参照)。
見出しが3つ以上あるページには、ページ内の目次も表示されます
([concepts.md](./concepts.ja.md#見出しへのリンク目次)参照)。ナビの見出しの横には、ライト/ダーク表示の
切り替えボタンが付きます([concepts.md](./concepts.ja.md#ライトダーク表示の切り替え)参照)。

`npx github:akilasatolu/tsuzuri#v1 init`で新しく作る設定ファイルでは、`true`になっています(v1.7.0以降)。

```
README.md             … ページ(リンク)
docs                  … ディレクトリ(見出し)
  getting-started.md
  guides              … サブディレクトリ(見出し)
    install.md
```

- **ページの表示名**: frontmatterの`title`を使います。`title`が無いページは本文の最初の`# 見出し`(h1)、
  それも無ければファイル名(例: `getting-started.md`)が表示されます。ナビだけ別の名前にしたいページには
  `title`を書いてください
  ([frontmatter.md](./frontmatter.ja.md#title)参照)。
- **並び順**: 起点のMarkdownからリンクをたどってページが見つかった順です。
  READMEなどでリンクを書いた順に並びます。ディレクトリは、その中で最初に
  見つかったページの位置に置かれます。
- **対象ページ**: 起点からリンクでたどれるページだけが載ります(リンクされていない
  Markdownは、同じディレクトリにあってもナビにもサイトにも含まれません)。

### FAVICON_FILE
生成されるサイトで使うfaviconの画像ファイルへの、リポジトリルートからの相対パスです。
未設定の場合は`<link rel="icon">`タグを出力しません(faviconなしの状態になります)。
指定したファイルが存在しない場合は、警告を出したうえで同じくfaviconなしでビルドを続けます。
リポジトリの外(`../`で始まるパスや絶対パス、リポジトリ外を指すシンボリックリンク)を指定した場合は、警告を出したうえで無視します。
なお、これは利用者がサイトに設定するfaviconであり、OSS本体自体のロゴ・favicon
(`assets/`配下)とは無関係です。

### SITE_NAME
全ページの`<meta property="og:site_name">`と、ナビゲーション有効時のナビ先頭の
サイトタイトルとして使われるサイト名です。また、起点のページ(`ROOT_MD`)にfrontmatterの`title`も
本文の最初の`# 見出し`(h1)も無い場合は、そのページのタイトルとナビでの表示名にも使われます(`README.md`にfrontmatterを書くと
GitHub上で表として表示されるため、書かずに済むようにしています)。省略した場合は、ビルド実行時の環境変数`GITHUB_REPOSITORY`
(`"owner/repo"`形式。GitHub Actions実行時は常に自動設定される既定の環境変数です)から、
`/`より後ろのリポジトリ名部分を自動的に採用します。`GITHUB_REPOSITORY`自体が
存在しない場合(ローカル実行時など)は空文字のままになります。

### CUSTOM_DOMAIN
カスタムドメインを使う場合のドメイン名です(スキームなし。例: `docs.example.com`)。
設定すると、出力ディレクトリ直下に`CNAME`ファイルが自動生成されます。
ホスト名として妥当でない値(例: `https://`付きの値やパスを含む値)を指定した場合は
警告を出したうえで空文字にフォールバックし、`CNAME`は生成されません。
詳細は[deployment.md](./deployment.ja.md)を参照してください。

### OGP_DEFAULT_IMAGE
frontmatterで`ogImage`を指定していないページに使う、既定のOGP画像です(リポジトリルートからの
相対パスまたは絶対URL)。省略した場合、`ogImage`が指定されていないページでは`og:image`タグ自体が
出力されません。

相対パスを指定した場合は、`https://<owner>.github.io/<repo>/assets/ogp.png`のような
サイトの絶対URLに変換され、画像ファイルもサイトにコピーされます(SNSは絶対URLでないと
OGP画像を読み込まないため)。リポジトリの外を指すパスは警告を出して無視します。

### STRICT_LINKS
リンクの問題があるときにビルドを失敗させるかどうかです。`true`または`false`(大文字小文字は
区別しません)で、デフォルトは`false`です。

- `false`(既定): リンク切れなどがあっても警告を出すだけで、そのまま公開します。
- `true`: 次のいずれかがあると、ビルドをエラーで終了します。ワークフローはそこで止まり、
  サイトは更新されません(前回公開した内容のまま残ります)。
  - リンク先のMarkdownファイルが存在しない(リンク切れ)
  - リポジトリの外を指すなどの理由で、たどらなかったリンク
  - リンクされた画像・ファイルが存在しない、またはコピーできない
  - リンクされたファイルの出力先が、生成したページやTsuzuriが作るファイル(`index.html`など)と重なる(v1.4.0以降)
  - 見出しへのリンク(`page.md#見出し`)の見出しが、リンク先のページに無い(v1.5.0以降)

問題の一覧はActionsタブのワークフロー実行ログに表示されます。

### LAST_UPDATED
各ページの末尾に、最終更新日(そのMarkdownファイルをgitで最後にコミットした日)を表示するかどうかです。
`true`または`false`で、デフォルトは`false`(表示しない)です。

`true`にすると、ワークフローはgitの全履歴を取得してからビルドします(履歴が長いリポジトリでは
少し時間がかかります)。gitの履歴が読めない場合は、警告を出して日付を表示せずにビルドします。

### EDIT_LINK
各ページの末尾に「このページを GitHub で編集」のリンクを付けるかどうかです(v1.30.0以降)。
`true`または`false`で、デフォルトは`false`(付けない)です。

`true`にすると、リンクからそのページのMarkdownファイルをGitHubの編集画面で開けます。読んだ人が
誤字や古い記述をその場で直して送れます(リポジトリに書き込めない人は、GitHubがフォークとプルリクエストの
作り方を案内します)。文言は日本語のページなら「このページを GitHub で編集」、英語のページなら
「Edit this page on GitHub」です。`LAST_UPDATED=true`なら、最終更新日と同じ行に並びます。
404ページには付きません。

リンク先は、ビルドしたブランチです。GitHub Actionsではpushされたブランチ(`TRIGGER_BRANCH`)、
手元では今のブランチとgitの`origin`から作ります。ブランチが分からないとき(タグをビルドした、
`origin`が無い、など)は、警告を出してリンクを付けません。このサイトも`EDIT_LINK=true`にしています。

### SITEMAP_JSON
デバッグ用の`sitemap.json`(収集したページ・画像、リンク切れの一覧など)を出力するかどうかです。
`true`または`false`で、デフォルトは`false`(出力しない)です。`true`にすると公開サイトにも
含まれ、リンク切れのファイル名なども外から見えるため、原因を調べるときだけ一時的に`true`に
することをおすすめします(詳細は[concepts.md](./concepts.ja.md)の「sitemap.jsonについて」)。

## 後方互換性について

`LANGUAGES`/`NAV_ENABLED`/`FAVICON_FILE`/`SITE_NAME`/`CUSTOM_DOMAIN`/`OGP_DEFAULT_IMAGE`/
`THEME`/`STRICT_LINKS`/`SITEMAP_JSON`/`LAST_UPDATED`/`EDIT_LINK`の11キーは、いずれも**すべて省略可能**です。1つも指定しなかった場合、
すべて上記のデフォルト値が適用され、これらのキーが導入される前のバージョンと
同じ挙動になります。既存の設定ファイル(旧4キーのみ)をそのまま使い続けても、
壊れることはありません。

ただし、サイトの言語だけは例外です。v1.28.0で`LANG`を廃止し、言語を書かなかったときの既定値が
`ja`から`en`に変わりました。`LANGUAGES`を書いていない設定ファイル(`LANG=ja`だけを書いたものを含む)では、
サイトが英語のサイト(`<html lang="en">`・英語の画面の文言)になります。日本語のサイトにするには
`LANGUAGES=ja`を書き足してください。
